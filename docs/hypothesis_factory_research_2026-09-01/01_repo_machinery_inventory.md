## 2. Strategy representation (what a generated hypothesis must produce)

- **`StrategySpec`** (`rust_engine/src/strategy/spec.rs:13`): `{name, version, params_hash, risk_profile}`; `params_hash` = SHA-256 of stable serde JSON (`stable_json_hash`, spec.rs:142). Every trade/order/report is keyed by it.
- **`StrategyVariant`** — the executable hypothesis for the momentum family (`rust_engine/src/backtest/strategies.rs:347-405`). Fields: `name`, `zone_config` (`strategy/decision.rs:504`), `skip_dead_zone`, `min_confidence`, `min_edge`, `decision_volatility_floor`, `position_pct`, `max_per_market_usd`, `max_projected_stressed_drawdown_pct`, degraded-mode knobs, `prefer_maker`/`maker_fill_prob`/`maker_seed`, `use_perfect_fill`, fee rates, `microstructure` (`strategy/microstructure.rs:34`), `selectivity` (`SelectivityFilter` strategies.rs:26 — require/deny causal-tag maps and value-sets over `DecisionRegime` tags), `exit` (`ExitConfig` strategies.rs:172 — settlement-basis exit, complete-set lock + trailing arm). Serialized JSON (single or array, validated by `rust_engine/src/backtest/variant_io.rs::read_variants`, duplicate-name rejecting) is directly replayable via `harness-sweep --variant-json` and `rolling-history --variant-json`. Registered exemplars with pinned hashes live in `deploy/promotions/evidence/strategy_registry/2026*_variant.json` (unit-tested hash pins, variant_io.rs:95-190).
- **Band family (the live winner)**: `BandPolicyParams` (`rust_engine/src/live/pipeline.rs:438-456`, `deny_unknown_fields`): `{family:"signal_favorite_band_official_v1", decision_seconds, entry_window_seconds, ask_floor, ask_cap, stake_usd, position_pct}` with `validate()` bounds (pipeline.rs:463) and venue floor $5 (pipeline.rs:434). Live instance: `deploy/promotions/band_policy_compound.json` (240s decision, 30s window, band (0.55, 0.92], stake $25, 25% compounding).
- **PromotionArtifact JSON** (`rust_engine/src/backtest/experiment.rs:248`; live example `deploy/promotions/band_promotion_compound.json`): `schema_version, inventory_model_version, created_at, source_report_hash, source_window, selected_strategy{StrategySpec}, strategy_params, data_manifest_hash, market_count/trades/win_rate/total_pnl/fees, dominant_zone(+share), risk_notes[], promotion_gate{...}`. ExperimentReport/VariantReport shape at experiment.rs:22-73.
- **Opportunity lane hypothesis contract**: causal-signal JSONL row spec (exact field list) in `docs/strategy_finding_architecture_v3_2026-08-08.md` (~line 25-45); policies evaluated over sealed parquet tables. The **late-window LLM DSL** (finite grid the LLM proposer chooses from: path/move composition, entry-price grid, decision margin, sigma buffer, direction) is documented at `docs/strategy_research_loop.md:88-108` — validator rejects out-of-grid/unknown fields/duplicates.
- Parameterizability: momentum family is highly parameterizable (~30 grid dims via harness-sweep flags); band family has exactly 6 tunable params but **no Rust backtest support** (see gaps).

## Factory parts list — automatable today vs missing for a closed loop

**Exists and scriptable today**
1. Executable hypothesis formats with hash pinning: StrategyVariant JSON (variant_io.rs) and BandPolicyParams JSON (pipeline.rs:438) — an LLM/generator only needs to emit these.
2. Deterministic evaluators: harness / harness-sweep / rolling-history / opportunity-exact-replay, all with JSON report artifacts and checkpointing.
3. Search primitives with feed-forward OOS gates: evolve-search (genetic), causal-policy-search, feature-filter-search, multi-guard-search, opportunity-policy/probability/liquidity/flow-search, plus materialize-* to close search→variant.
4. Gate machinery: promote/aggregate-promote/robust-promote (Wilson, PBO, neighbors, zone concentration), one-shot fresh gates with CONSUMED markers, terminal family `*-decision` verdicts with budget enforcement.
5. Candidate lifecycle registry + audit + durable evidence export (registry-mark/audit/evidence-export; docs/strategy_registry.json).
6. A scheduler/coordinator with locks, resource policy, SQLite ledger, content-addressed dedup, and a proven LLM-proposer harness with validator + deterministic fallback.
7. Promotion → live binding: band-promotion-artifact → preflight/release-manifest.

**Missing / gaps for a closed hypothesis factory**
1. **No generic candidate queue**: the SQLite ledger and `logs/strategy-research/candidates/` are lane-specific (late_window only); there is no CLI/API to enqueue an arbitrary new hypothesis family or StrategyVariant into the funnel — each family so far required hand-written Rust subcommands + preregistration markdown.
2. **The live-winning band family has no Rust backtest**: no `band` code in `rust_engine/src/backtest/*` (only the momentum family and opportunity lanes); band validation was a bespoke Python public-data gate (`fresh_gate_public_v1.py`, constants hard-coded at lines 31-38) + capture fill-replay. A band-parameter sweep (ask_floor/cap, decision_seconds) currently cannot run through the L2 harness.
3. **LLM lane paused and DSL-bound**: only the late-window finite DSL exists; no DSL/schema for proposing new information sources or band-style families; prompt policy restricted to public aggregates until LM Studio logging is fixed (docs/strategy_research_loop.md:140-156).
4. **No auto-promotion by design**: coordinator allowlist deliberately excludes materialization/registry-promotion/deployment; promotion stays human-reviewed — the "closed" loop can at most emit a `paper_only` bounded shadow verdict (doc lines 376-383).
5. **No automated data-freshness pipeline in-repo**: pmxt-download and distill are manual/one-off; local distilled coverage ends 2026-08-24T01; no scheduled backfill job keeps the Mac's replay data fresh (fresh-window rule in CLAUDE.md §6 then blocks candidates).
6. **No research auto-reporting**: status.json + launchd logs only; Telegram commands (main.rs:1112-1140) serve live monitoring, not research-cycle summaries.
7. **Preregistration is markdown-first**: gate contracts are frozen JSON in some lanes (funnel v3) but there is no generator that turns a new hypothesis into a machine-checked preregistration + budget object.
